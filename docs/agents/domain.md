# Domain docs

## Before exploring

Read root `GLOSSARY.md`, if present, and the ADRs in `docs/adr/`
that concern the area being explored.

If these documents do not exist, proceed silently.
The domain-modeling skill creates them as terms and decisions are resolved.

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md`: vocabulary for the whole repository.
- `docs/adr/`: architecture decision records.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues,
proposals, code, and tests. If a term is missing, reconsider whether
it belongs to the domain or record the gap for domain-modeling.

## Decisions

If a proposal contradicts an existing ADR, identify the ADR and explain
why the decision should be reconsidered.
