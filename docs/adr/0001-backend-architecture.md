# Архитектура бэкенда календаря

Для небольшого сервиса выбираем слоистую архитектуру с направлением зависимостей
к домену и используем идеи DDD для языка и инвариантов. Полный набор шаблонов
Clean Architecture и DDD добавил бы сложность без необходимой сейчас пользы.

HTTP-слой реализует сгенерированный из OpenAPI интерфейс и преобразует API-типы
во внутренние. Сценарии приложения связывают доменные правила, время и хранилище;
домен не зависит от HTTP, OpenAPI и JSON. Хранилище в памяти реализует необходимый
сценариям контракт. Интерфейсы вводим на реальных границах, в том числе для
хранилища и управляемого времени, а не для каждого компонента заранее.

Проверка пересечения и сохранение записи выполняются атомарно: при одновременных
запросах на пересекающиеся интервалы может успешно сохраниться только одна запись.
Для хранилища одного процесса это можно обеспечить блокировкой на время проверки
и сохранения. Доменная логика и сгенерированные API-типы остаются раздельными.
